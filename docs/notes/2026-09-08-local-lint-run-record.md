# ローカル lint の要約と全文保存

## 要約

`settings`・`github-workflows`・`techbook-template` の横断整理を進めている．
その一環として，`lint-md` の繰り返し利用で読む出力を制限できるようにした．
契約は [push 前ローカル Markdown lint](../local-lint.md) に記す．

## 判断

対象選定と指摘の集計は決定論的な処理であり，既存スクリプトを使う．
AI が担うのは，指摘の意味，変更の要否，修正方法の判断である．
要約のために対象集合を狭めると，指摘の見逃しにつながる．
そこで集計後の表示だけを制限し，省略件数と全文への参照を残した．

CI と共用する `count-lint-findings.py` の出力は変更しない．
既存の renderer に保存済み集計の表示を加え，再実行なしで詳細を読めるようにした．
通常出力の既定と終了コード 0・1・2 は保つ．
記録は要約・JSON の指定時，または保存先を明示した場合に作る．

作業用の複製と保存記録の寿命は異なる．
複製と runtime config は終了時に回収し，元レポートと診断は保存する．
実行失敗の件数を 0 に置き換えない．
対象なしと検査成功も区別し，選定件数を検査済み件数とは呼ばない．
これは [Issue #134 の実装知見](2026-09-02-issue134-local-md-lint.md) にある，
絞り込みの失敗を「指摘なし」と見誤る問題を再発させないためである．

## コメントの扱い

`lint-md.sh` の冒頭コメントは `--help` が直接表示するため残す．
改行処理の経緯は既存文書と重複していたため短縮した．
相対構造，単独 CR，末尾改行を保つ制約はコードの近くに残す．
コメントの行数だけを品質指標にせず，説明先と実行上の役割を確認して整理する．

## 検証方針と限界

実装前に，未実装の記録関数と CLI オプションでテストが失敗することを確認した．
テストでは指摘数，終了コード，全文の保持，保存先，複製の回収を観測する．
既存の対象選定・改行・パス突合の回帰テストも通す．
共有 renderer を使う Python suite と repo-local Shell quality gate を実行する．

記録は監査用の完全な環境再現ではない．
HEAD SHA だけでは未コミット変更や設定の差異を再現できない．
SHA・設定・検査対象を結び付ける横断契約は，後続の検証基盤の整理で扱う．
この変更では reusable workflow と caller の SHA pin を更新しない．
